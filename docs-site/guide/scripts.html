插件安装与使用 ​

适用于 AiVerse 1.0.0 及以上。本文讲怎么装、怎么用；想自己写插件请看 插件开发指南。

插件是给 AiVerse 扩展能力的 zip 包：装好后可以给 AI 增加新工具、新技能、新供应商，也能在设置、侧栏、聊天菜单等位置多出新的界面入口，或接入新的 MCP 服务器。所有插件都在「设置 → 插件」里统一管理。

提示

插件来自第三方开发者，安装前请确认来源可信。插件在容器里以独立进程运行（Node 或 Python），具备读写文件、联网、执行命令的能力；只有纯页面型插件跑在 WebView 沙箱里。商店会对插件做安全审计，但宿主无法保证第三方插件的行为。

插件能带来什么 ​

  • AI 新工具：向 AI 注册可调用的工具，装好后出现在 AI 的工具列表里，像内置工具一样被调用。

  • 技能与子代理：给 AI 补充某类任务的标准流程（技能）或专职角色（子代理）。

  • 新的界面入口：在设置的某个分区末尾、侧栏底部、聊天菜单、文件树长按菜单等位置新增入口，点进去是插件提供的页面。

  • MCP 服务器：把外部工具通过 MCP 接进来（见 MCP 服务器），随插件启停。

  • AI 供应商：在「设置 → AI 供应商」里多一个带「插件」标签的供应商。

  • 悬浮窗、备份参与等：部分插件还会申请悬浮窗（overlay）、参与备份、调用 Shizuku 等能力，这些都需要你在插件详情里单独授权；代发起模型请求为声明式能力，会计入对应渠道用量。

说明

只注册了「工具」、没有任何界面入口的插件，在界面上不会多出任何按钮，这是正常的——它的能力直接体现在 AI 的工具列表里。

三种安装方式 ​

打开「设置 → 插件」，顶部有「已安装」「商店」「开发中」几个标签页，右上角是「+」按钮。

方式一：从 zip 包安装 ​

  1. 拿到插件的 zip 包（不要解压）。
  2. 进入「设置 → 插件」，点右上角「+」，从文件里选中这个 zip。
  3. 宿主会解包、校验清单并安装，装好后在「已安装」列表出现条目。

注意

zip 的根目录要直接是插件内容（含 plugin.json），不要把外层文件夹一起压进去；单包安装上限 16MB，超出会安装失败。

插件包命名规则（发布到商店必读）

提交到商店的插件包，压缩包文件名必须严格遵守：

作者名.插件名_版本号.zip
  • ID 第一段必须是作者名，不能以 aiverse 开头：插件 id 形如 作者名.插件名（例如 yhdmgf.desktop-pet），宿主强制校验 id 第一段等于发布者 publisher（作者名）。aiverse.* 是官方保留命名空间，第三方插件用它会被商店判为冒充官方并拒绝。
  • 作者名规则：小写字母开头，只含小写字母、数字、连字符（^[a-z][a-z0-9-]*$）。
  • 版本号：用下划线 _ 连接，语义化版本、不带 v 前缀（如 yhdmgf.desktop-pet_1.1.0.zip）。
  • 文件名不符合该格式会被商店上传/审核环节拒绝。开发阶段本地导入 zip 不受此命名限制，但发布必须遵守。

方式二：从插件商店安装 ​

  1. 进入「设置 → 插件」，切到「商店」标签页。
  2. 浏览或搜索插件，点进详情查看介绍、版本、作者与官方标识。
  3. 点安装，宿主下载并安装，装好出现在「已安装」列表。

商店列表来自官方插件索引，会不定期更新；找不到新插件时在商店页下拉刷新即可。

方式三：开发中目录（边改边试） ​

适合自己写插件、或想直接改插件源码的场景，不用反复导入 zip：

  1. 「设置 → 插件」右上角点齿轮，打开开发者模式。
  2. 开启后，~/.aiverse/plugin-dev/<项目目录>/ 下每个含 plugin.json 的子目录都会出现在「开发中」标签页。
  3. 改动这些目录里的文件会自动重打包替换，无需重新导入。

提示

想动手写插件，看 插件开发指南：里面有包结构、清单字段、可声明的全部能力，以及一个能直接跑的最小示例。

启用与停用 ​

「已安装」列表里每个插件卡片右侧有一个开关：

  • 开：插件能力生效——注册的工具、界面入口、MCP 服务器等全部接入。
  • 关：插件能力整体撤销，已注册的工具和入口消失，但插件文件保留。

开关是灰色点不动的，说明这个插件的清单或内容不可用（解析失败、摘要不符或贡献缺失，插件状态为错误）。安装导入时的预览会逐条指出具体的字段问题；已装插件出现这种情况属于插件本身的错误，需要开发者修复。

管理已安装的插件 ​

点某个插件卡片进入详情页，可以：

  • 查看插件的名称、版本、发布者、许可证、源码仓库、来源与贡献内容。
  • 查看并单独授权特殊能力：Shizuku 命令、悬浮窗、备份读写可单独授权；模型调用为声明式，不单独授权。
  • 有配置页的插件，详情页顶部会多出「插件管理 / 插件配置」分段标签，切到「插件配置」即可进入。
  • 停用 / 卸载：卸载会删除插件文件，不可恢复。

更新：同一个插件只有在版本号变化时才会被识别为「更新」；版本号没变重新安装会被当作替换而非更新。

排查清单 ​

装了插件却没达到预期时，按顺序确认：

  1. 插件在「已安装」列表里吗？不在 → 安装没走完，重新装一次。
  2. 开关能点吗？灰的 → 清单解析失败，详情页会指出具体字段。
  3. 开了开关吗？关闭状态下插件的工具和入口都不会生效。
  4. 界面里找不到入口？只注册了工具的插件本来就没有界面入口，去 AI 的工具列表里找；有界面入口的插件，按开发文档里的槽位表确认它声明在哪个位置。
  5. 商店里没有某个插件？下拉刷新商店；商店索引在进入商店、下拉刷新或启动检查时更新，离线时显示上次缓存，刚发布的插件需要等一会。
  6. 还是不行？把插件详情页的报错信息反馈给插件作者。
